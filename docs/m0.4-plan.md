# M0.4 plan: the first real Charm view

**Status:** Approved for implementation · 2026-10-20
**Scope:** The M0.4 items of [the roadmap](roadmap.md). It follows the
[terminal direction](tui-design.md) and the [contracts](contracts.md), and changes
no M0.3 execution decision.

M0.4 adds one way to watch an operation: `eregion operations follow`. The same
reducer feeds three presenters (NDJSON/JSON, plain text, and an interactive Charm
view). The viewer reads through the existing API client. It never enqueues work,
never opens SSH, and never cancels an operation it stops watching.

## Decision summary

| # | Question | Decision |
| --- | --- | --- |
| 1 | Where the logic lives | `internal/viewer`: a plain Go reducer with no Charm import. Fixture tests, the follow loop, and every presenter use the same `Model`. |
| 2 | Transport | Poll the existing API: `GET /v1/operations/{id}` for the snapshot and `GET /v1/operations/{id}/events?after=N` for pages. No SSE or server change in M0.4. |
| 3 | Command | `eregion operations follow <operation_id>` with `--output plain\|ndjson\|json`, `--interactive`, `--ascii`, `--reduced-motion`, `--poll-interval`. `operations test --follow` submits, then follows the same operation. |
| 4 | Mode selection | Explicit machine output wins. Plain is the default on a terminal and on a pipe. `--interactive` starts Bubble Tea only when stdin and stdout are terminals; otherwise it fails with `usage_error`. Machine output never starts Bubble Tea. |
| 5 | JSON vs NDJSON | `--output ndjson` streams every event record, then one final result record. `--json` waits and emits one envelope with the final snapshot, the event count, and the last cursor. |
| 6 | Exit status | `0` once the viewer has observed a terminal state, whatever that state is. `data.state` says the outcome. Leaving early (`q`, Ctrl+C, SIGTERM) exits `130` with `cancelled`, prints the operation ID and the resume command, and never calls cancel. |
| 7 | Observation states | `connecting`, `live`, `stale`, `reconnecting`, `closed` are viewer states, separate from operation states. Stale after 3 failed polls or 10 s without a successful response. A stale view says **last known** and stops the spinner. |
| 8 | Replay and gaps | Deduplicate by sequence. A page that skips a sequence is a gap: refetch from the cursor; an expired cursor (`precondition_failed`) is shown, not skipped. After a reconnect, refresh the snapshot before trusting the state. |
| 9 | Stages | Only stages seen in `step` events are listed. There is no planned-stage list, so there is no pending row and no percentage. A `progress` event with a known total shows a bar. |
| 10 | Charm stack | Bubble Tea v2, Bubbles v2, Lip Gloss v2 at released, pinned versions (`charm.land/*/v2`). |
| 11 | Terminal safety | Every server string goes through the existing terminal-safe sanitizer and redaction registry before any presenter sees it. Widths are measured in cells. |
| 12 | Accessibility | `NO_COLOR` removes colour, not words or glyphs. `--ascii` (or `TERM=dumb`) swaps glyphs. `--reduced-motion` (or `EREGION_REDUCED_MOTION=1`) replaces the spinner with a static label; elapsed time keeps updating. |

## 1. Reducer (`internal/viewer`)

Inputs are observations, not Charm messages:

- `Snapshot(contract.Operation, at)`: authoritative state; replaces the state
  derived from events when its `last_sequence` is at least as new.
- `Page([]contract.Event, at)`: appends events in sequence order; drops
  duplicates; reports a gap when the first new sequence is not `last+1`.
- `PollFailed(err, at)` / `PollSucceeded(at)`: drive the observation state.
- `Tick(now)`: updates elapsed time and staleness only.

`Model` exposes the operation identity, the operation state, the attempt and its
changes, the stage rows (name, status, attempt, first/last seen), a bounded event
ring (default 2000 lines), the last measured progress, the observation state and
its age, the cancellation flags (requested vs acknowledged), the terminal error
code, and the elapsed and queued durations from server timestamps. The model never
invents a stage, a duration, or a percentage.

## 2. Follow loop

`viewer.Follow(ctx, client, id, opts, emit)` polls the snapshot and pages events
until a terminal state is observed **and** the event cursor has reached the
snapshot's `last_sequence`. It backs off from the poll interval (default 500 ms)
to 5 s on errors. Context cancellation ends the loop and returns `cancelled`; it
never calls `RequestCancel`. The client interface is the subset of
`operations.Service` the API client already implements.

## 3. Presenters

- **NDJSON:** the existing `output.Stream`; one event record per new event, then
  one final result.
- **Plain:** append-only lines: one line per event with time, sequence, kind,
  stage, and the sanitized message; one line per observation change
  (`reconnecting`, `stale: last known running 12s ago`); a summary line at the
  end. No cursor motion, no colour.
- **Interactive (`internal/tui`):** header (context/API host, target, operation
  ID, state badge), stage list, event viewport, and status bar (freshness,
  follow/pause, key hints). Wide: stages beside events. Standard: stages above
  events. Narrow: one column. Very small: a compact summary. Keys: `?` help,
  `tab` pane, `j/k` and arrows, `g/G`, `space` pause follow, `q`/Ctrl+C detach.

## 4. Tests

- Reducer fixtures: ordered, replayed, duplicate, and gapped pages; stale and
  newer snapshots; attempt change; reconnect; cancellation requested then
  acknowledged; failure with an error code; success.
- Follow loop with a fake client: connection loss and recovery, a detach that
  makes no cancel call, termination only after the cursor catches up.
- Golden renders: narrow, standard, wide, tiny; colour, no colour, ASCII; long
  labels; hostile ANSI/OSC log text; a redacted secret.
- Interactive program tests: resize, navigation, help, pause, detach.
- CLI contract tests: `follow` metadata, output modes, `--interactive` without a
  TTY, exit codes.
- Integration: the real API and worker run `diagnostic.test`; `follow` succeeds
  over NDJSON, JSON, and plain text, and a detached viewer leaves the operation
  running to completion.

## 5. Local trial

`just dev-up` starts a throwaway PostgreSQL, migrates, writes a local auth file,
and starts `serve` with workers; `just dev-down` removes them. The control-plane
guide shows `operations test --follow --interactive`.

## Out of scope

SSE or long-poll on the server, dashboards, fleet views, cancel keys in the
viewer, and remote node selection from the viewer.
